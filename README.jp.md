# 🐸 KeroTranslate

[English](README.md)

[公式サイト](https://kurayan.github.io/KeroTranslate/) · [プライバシーポリシー](https://kurayan.github.io/KeroTranslate/privacy.jp.html)

YouTube Liveの音声字幕と、自分のコメント翻訳を支援するChrome拡張です。
配信を見ながら原文・翻訳を読み、自分のコメントは **Original → MTL → re-MTL** で意味を確認できます。

**INSERTはYouTubeの入力欄に下書きを入れるだけ。投稿は自分で行います。**

現在のバージョン: **Beta 0.5.1**（2026-10-25）。
リポジトリ・プロダクトの正式表記は **KeroTranslate** です。

最新版は[Chromeウェブストア](https://chromewebstore.google.com/detail/mkpjddfijhnmgnjelchaameoknomplel)からインストールできます。開発者モードで使う場合は、このリポジトリの `extension/` フォルダーを読み込んでください。下記のv0.2.0-betaリンクは旧版です。

## パネルのテーマ

メインパネル上部の **Dark / Light** で配色を切り替えられます。初期値はDarkです。選択は同じChromeプロファイルに保存され、再読み込み・Chrome再起動後も保持されます。設定画面の **03 / Panel appearance** からも変更できます。

メインパネルでの切り替えは入力中のコメント、翻訳処理、字幕の音声認識を中断しません。設定画面のSaveは従来どおり音声認識を停止します。テーマはKeroのコメントパネルだけに適用し、字幕オーバーレイやYouTubeの配色・全画面動作は変更しません。

Ambient light for YouTubeとの併用環境で、全画面チャットの文字が読めなくなる症状を確認しました。同拡張を無効にしてページを再読み込みすると改善しました。Keroによる他拡張の配色上書きは行いません。


## アーカイブの字幕・翻訳

アーカイブを含むYouTubeの通常の動画ページ（`/watch`）で使えます。動画を再生し、Keroのツールバーアイコンから **Start captions** を押してください。チャットリプレイには字幕専用パネルを表示します。**Start captions / Stop**、**Request gap**、**Caption hold**、テーマ切り替え、最小化を使用できます。コメント入力・MTL・re-MTL・INSERTはありません。Chromeの権限制約により、そのタブでの初回開始にはツールバーポップアップのStart captionsが必要になる場合があります。チャットリプレイがない動画ではポップアップを使用してください。

再生中のタブ音声を認識するため、動画全体の一括文字起こし・字幕ファイル取得ではありません。設定の **Original only** は文字起こしのみ、**Original + MTL** は翻訳付き字幕です。シーク・再生終了時は古い訳文が混ざらないよう字幕処理を停止します。シーク後は再度 **Start captions** を押してください。一時停止だけではセッションは終了しないため、長く離れる場合は **Stop** を押してください。

## Chromeに読み込む

**まだBeta版のため、Chromeのデベロッパーモードを有効にして読み込んでください。**

1. 上のリンクからReleaseページを開き、**Assets** 内の **KeroTranslate-Extension.zip** をダウンロードして展開します。ソースから使う場合は `extension` フォルダーを使います。
2. Chrome 116以降で `chrome://extensions` を開き、デベロッパーモードを有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」で、`manifest.json` が直下にあるフォルダーを選びます。
4. 開いているYouTubeページを再読み込みします。
5. 拡張アイコンの **Settings & API keys** またはメインパネルの歯車から設定を開きます。
6. 音声認識・翻訳のProviderを選び、対応するAPIキーを入力して保存します。初期設定は音声認識がDeepgram、翻訳がGeminiです。モデルIDはアカウントで使えるものを設定してください。
7. YouTube Liveの視聴タブで **ツールバーのKeroTranslateアイコン → Start captions** を押します。ポップアップ内で開始・停止まで完結します。チャット下のメインパネルにも開始・停止ボタンがあります。

Chromeのタブ音声取得には、そのタブで拡張を呼び出す操作が必要です。新しいタブではツールバーのポップアップ内のStart captionsを使ってください。メインパネルへ戻る必要はありません。開始後はポップアップを閉じても字幕が続き、どちらのStopでも停止できます。音声は対象タブから取得し、マイクは使いません。

### 更新するとき

1. Stopで字幕を停止し、読み込み済みフォルダーのファイルを更新します。
2. Chromeの拡張機能管理画面でKeroTranslateを再読み込みします。
3. YouTubeページも再読み込みします。
4. 対象YouTubeタブのツールバーポップアップから再開します。同じChromeプロファイル・拡張の読み込み元であれば、保存済みキーは保持されます。

**保存したAPIキーはChrome終了・再起動や拡張の再読み込み後も保持されます。** このChromeプロファイル内のローカル保存で、他の端末には同期しません。設定の **Delete all API keys** で削除できます。拡張の削除や保存データの消去でもキーは消えます。設定保存は引き続き実行中の音声取得を停止します。更新時は同じ読み込み元フォルダーを使ってください。別フォルダーを読み込むと別の拡張として扱われる場合があります。

0.1.10以前からの更新では、残っているセッション内キーを移行します。旧版のキーが更新時にすでに消えていた場合だけ、新版で一度入力・保存してください。

## Providerの選択

音声認識と翻訳は独立して選べます。たとえば **OpenAI STT → DeepL翻訳**、**Deepgram STT → DeepSeek翻訳** が可能です。コメントのMTLとre-MTLは同じ翻訳Providerを使います。

**Deepgramの無料クレジット＋Geminiの無料利用枠で動作確認済みです。** [APIキーの取得・設定方法はこちら（初心者向け）](docs/API-KEYS.jp.md)。無料で使える範囲や条件も説明しています。

| Provider | 音声認識（STT） | 翻訳・再翻訳 | 設定 |
|---|---|---|---|
| Deepgram | Nova-3 | — | Deepgram APIキー |
| Gemini | — | 対応 | Gemini APIキー・モデルID |
| OpenAI | gpt-live-transcribe | 対応 | OpenAI APIキー。翻訳初期モデルはgpt-4.1-mini |
| DeepL | Voice API（有料・利用権限が必要） | API Free / API Pro | DeepL APIキー・翻訳用プラン |
| DeepSeek | — | 対応 | DeepSeek APIキー。初期モデルはdeepseek-flash |

**0.1.6で追加した接続は実験的です。実APIでの通し確認はまだ行っていません。** モデルの利用権限・地域・残高は各APIアカウントで確認してください。ChatGPTやDeepLウェブ版の購読とAPI契約は別です。

- OpenAI STTは途中テキストを先行表示し、約600msの静かな区間で確定します。音が続く場合は約8秒を上限に区切ります。これは音量を用いた簡易判定で、BGMやゲーム音が多い配信は区切りや品質の実測が必要です。現在、このしきい値の設定UIはありません。
- DeepLは翻訳用の **API Free / API Pro** をキーに合わせて選びます。Voiceはこの選択に関係なく有料エンドポイントを使い、Voice API利用権限が必要です。音声認識のみを依頼し、翻訳は選択したProviderへ別途送ります。
- DeepSeekは翻訳用です。公開APIで確認できた範囲にSTT用エンドポイントがないため、音声認識の選択肢には含めていません。翻訳はThinkingを無効にして要求します。
- 選択中のProviderに必要なキーと設定を表示します。切り替えても別Providerの保存済みキーは保持され、**Delete all API keys** でまとめて削除できます。

接続方式・公式資料・実機確認項目は [Provider追加ノート](docs/PROVIDERS-0.1.6.jp.md) にまとめています。

## 配信字幕

- **partial（認識中）**: 受信した原文を薄色＋「…」で先に表示。同じ区間の修正はその場で更新します。
- **final（確定）**: 原文を通常色に切り替え、その後に翻訳を開始します。partialごとに翻訳APIは呼びません。
- 前の翻訳と対応する原文を残し、新しい認識テキストは区切り線の下に表示します。遅れて届いた翻訳が新しいpartialを消さないようにしています。
- 翻訳待ちの間は表示を維持し、翻訳到着後から表示時間を数えます。新しい翻訳が来たら置き換えます。
- 翻訳が追いつかない場合、進行中の1件を完了させ、待機中は最新1区間だけを残します。途中の区間は省略されるため、全文記録用途ではありません。

**Settings → 04 / Captions** で調整できます。

| 設定 | 選択肢 / 初期値 |
|---|---|
| Show | Original + MTL / Original only / MTL only。初期値は両方 |
| Caption size | 75 / 100 / 125 / 150 / 200%。初期値100% |
| Keep captions after translation | 5 / 7 / 10 / 15 / 20秒。初期値5秒 |
| Maximum lines per language | 1 / 2行。初期値2行。認識中の行にも適用 |
| Position | 上・中央・下 × 左・中央・右の9か所。初期値は下中央 |

字幕保持の初期値5秒は、翻訳が届いてから数えます。読み終える前に消える場合は7〜10秒、長文では15〜20秒へ延ばすと読みやすくなります。次の翻訳が届くと早めに置き換わることがあり、翻訳待ちの間は設定時間より長く表示されます。保持時間は表示だけの設定で、翻訳速度やリクエスト頻度は変わりません。保存済み設定は保持されるため、既存ユーザーは必要に応じて5秒へ変更してください。

partialを見るには **Original + MTL** または **Original only** を選びます。MTL onlyでは原文を表示しません。Original onlyでは字幕用の翻訳APIを呼ばず、finalの表示後から表示時間を数えます。

**Settings → 02 / Languages** のSpeech languageが配信の音声言語、Translate captions intoが字幕の翻訳先です。コメント欄のJA → EN / EN → JAとは独立しています。日本語配信ならSpeech languageをJapaneseに設定できます。Mixed languagesは実験的です。

## メインパネルから時間を調整

**メインパネル右上**の2項目で調整できます。迷ったら **Request gap：1 s／Caption hold：5 s** から試してください。画面の **s は「秒」**です。

| パネルの項目／設定画面での名前 | 何を変える？ | 初期値／選べる値 | 調整する目安 |
|---|---|---|---|
| **Request gap**／**Minimum interval between translation requests** | 翻訳サービスへ依頼を送る「開始時刻どうしの最小間隔」。字幕・コメント翻訳・re-MTL（逆翻訳）に共通です。 | **1秒**／0.5・1・2・4・6・12秒 | 送りすぎによる制限エラーが出るときは長くします。長い設定を短くすると待ち時間を減らせる場合がありますが、サービス自体の翻訳処理が速くなるわけではありません。 |
| **Caption hold**／**Keep captions after translation** | 翻訳が届いてから、字幕を画面に残す時間。 | **5秒**／5・7・10・15・20秒 | 読み終える前に消えるなら **7秒・10秒**、長文なら **15秒・20秒**を試します。翻訳の送信頻度や処理速度は変わりません。 |

| こんなとき | 調整・確認すること |
|---|---|
| 字幕を読み切る前に消えてしまう | **Caption hold**を長くします。ただし次の翻訳が届くと早めに置き換わることがあり、次の翻訳を待つ間は設定より長く残ることもあります。 |
| コメント翻訳やre-MTLの完了が遅い | **Request gap**を確認。6秒・12秒なら、利用枠に収まる範囲で短くしてみます。通信や翻訳サービス側の処理時間による遅れは残ります。 |
| 回数制限のエラーが出る | 表示された待ち時間が過ぎてから、**Request gap**を2秒・4秒へ。制限が厳しければ6秒・12秒へ延ばします。利用枠自体を使い切った場合は、間隔変更だけでは解消しないためサービスの利用状況を確認してください。 |

メインパネルで値を選ぶと**自動保存**され、設定画面・他のYouTubeタブにも共有されます。狭いパネルでは下の行に表示されます。ここで調整しても字幕取得は続き、下書きや編集中の訳文は残ります。Request gapは待機中の送信にも反映されますが、進行中の翻訳を中断したり、サービスから指定された待ち時間を解除したりはしません。Caption holdは次に字幕の表示時間を数え始めるときから適用されます。更新しても保存済みの値は保持するため、以前から使っている場合は上記の初期値と異なることがあります。

ヘッダーの **−** でパネルを最小化、**+** で戻せます。下書き・翻訳・字幕取得は維持されます。最小化状態はパネルの再生成やページの再読み込みまで保持します。

re-MTLの下に **Retry all** を常設しました。Originalに文字があれば処理中でも使えます（IME変換中は無効）。前のコメント処理を取り消し、現在のOriginalから翻訳と意味確認を両方やり直します。手動編集したMTLも作り直されるため、必要な訳文は先に控えてください。API制限の待機時間は解除しません。コメント処理が応答しない場合は2分でタイムアウトします。パネルとポップアップのエラー文は、後続の状態更新が来ても最低1秒表示します。

コメントの翻訳と逆翻訳を一つのキュー処理にまとめ、その間へ字幕翻訳が割り込まないようにしました。各API送信の間隔は設定値に従います。MTLの手動編集では意味確認のみ、Retry allでは両工程を実行します。

字幕の通常の翻訳失敗後は、連続失敗に応じて1〜10秒待ち、新しい発話から再開します。認識は継続し、待機中の発話は翻訳対象から間引きます。API制限時は下記の待機時間に従います。字幕は実行中と最新の待機区間だけを保持し、共有キューが上限に達した場合も既存の処理やAPI制限待機をリセットしません。今回確認した停止原因はブラウザーのタイマー呼び出しだったため、オーバーフロー回数によるリセット設定は追加していません。

## 翻訳リクエストの調整

字幕・コメントのMTL・re-MTLは、バックグラウンドの共通キューから送信します。同じProviderへのHTTP翻訳は同時に1件だけ。待機中はコメントを優先し、進行中の字幕翻訳は完了を待ちます。音声認識ストリームはこのキューの対象外です。

**リクエストは、翻訳サービス（API）への依頼1回**のことです。コメント1件は通常、**翻訳とre-MTLで2回**使います。字幕も同じ利用枠に数えます。パネルの **Request gap** と設定画面の **Minimum interval between translation requests** は同じ設定です。

| Request gap | 1分あたりの送信開始回数の上限目安※ | 選び方 |
|---|---:|---|
| **0.5秒** | 120回 | 最も短い間隔。多い送信回数に対応した利用枠がある場合に選びます。 |
| **1秒（初期値）** | 60回 | 待ち時間を抑えるための開始目安。契約しているサービスの利用枠も確認してください。 |
| **2秒** | 30回 | 1秒で回数制限が出る場合に、まず送信頻度を下げる選択肢。 |
| **4秒** | 15回 | さらに送信頻度を下げます。翻訳からre-MTLまでの待ちも長くなります。 |
| **6秒** | 10回 | 回数制限が厳しい場合向け。コメントの完了待ちが目立ちやすくなります。 |
| **12秒** | 5回 | 最も長い間隔。反応の速さより送信頻度の低さを優先する設定です。 |

※「60秒 ÷ 間隔」で求めた目安で、**契約プランの利用枠や、翻訳の完了回数を保証する数字ではありません**。同じサービスへの翻訳は同時に1件だけなので、応答が遅い場合や一時停止中は回数が減ります。間隔を短くすると利用量・費用が増える場合があります。また、1日の利用上限や文章量に応じた制限は別にかかります。**1秒に設定しても、1秒で翻訳が届くとは限りません。**

429などの制限エラー後は、そのProviderへの送信を一時停止します。Retry-Afterが返ればその時間（最大24時間）、なければ30秒です。失敗した文・待機中の文は自動再送しません。コメントは表示された待機時間の後にRetry all、字幕は次に届く新しい区間で再開します。Stop・入力変更・キー削除は不要になった待機リクエストを取り消します。

この制御は同時送信と送信集中への対策です。トークン数・日次枠・同じAPIプロジェクトを使う別アプリの通信までは管理しません。拡張の再読み込み・worker再起動でキューと一時停止状態はリセットされます。[Gemini公式の制限説明](https://ai.google.dev/gemini-api/docs/rate-limits)も参照してください。

## コメント作成

Composer original languageの初期値は **English → Japanese**（英語入力→日本語訳）です。保存済みの設定は保持します。メインパネルには作成済みの緑・白のカエルアイコンを表示します。

1. Originalにコメントを入力し、JA → EN / EN → JAを選びます。
2. MTL（翻訳）とre-MTL（意味確認用の再翻訳）を確認します。再翻訳は正確さの保証ではありません。
3. 必要ならMTLを直接編集します。編集した文からre-MTLを更新します。
4. OriginalまたはMTLの **INSERT** でYouTubeの入力欄へ挿入します。MTLは最新の再翻訳が完了してから挿入できます。
5. YouTube側で確認し、自分で送信します。

既存の下書きがある場合は **Replace draft / Keep draft** を選びます。挿入は200文字以内（JavaScriptの文字列長基準）です。日本語IME入力中は翻訳を待ち、古い応答が新しい入力を上書きしないようにしています。

## 困ったとき

| 症状 | 確認すること |
|---|---|
| パネルが出ない | 通常のYouTube Live視聴画面でライブチャットを開き、YouTubeを再読み込み |
| オーバーレイ初期化エラー | 読み込み中の短い失敗は自動再試行。拡張更新直後はYouTubeを一度再読み込み。配信動画の読み込み後にツールバーから開始 |
| 字幕が出ない | 拡張ポップアップの **Test overlay** で固定字幕が出るか確認。音声・APIを使わず表示だけを試せます |
| LISTENINGなのに字幕がない | 接続中という表示だけでは認識成功は分かりません。配信音声、Speech language、Provider側の利用状況を確認 |
| 開始時に拡張アイコンを開く案内 | そのYouTubeタブで拡張アイコンを開き、ポップアップ内のStart captionsを押す |
| NO_SPEECH | 15秒以上認識結果が届いていない状態。実際の無音を測定した表示ではありません |
| INSERTできない | ログイン・チャットの投稿条件と入力欄を確認。最新版でYouTubeを再読み込み。入力欄はYouTubeのDOM変更の影響を受けます |
| 更新後にAPIキー不足 | 同じChromeプロファイル・読み込み元を更新したか確認。旧セッション保存版からの更新時だけ、一度入力・保存が必要な場合があります |
| 以前のDemo設定が残っている | Deepgram／Geminiに補正されます。対応するキーを設定するか、別のProviderを選んでください |

## キーとデータ

- APIキーは `chrome.storage.local` に保存し、アクセスを信頼された拡張コンテキストに制限します。content scriptやYouTubeのDOMへ返さず、Chrome Syncにも送りません。ローカル保存は暗号化された認証情報保管庫ではありません。音声取得状態・使用量の指標は引き続きセッション保存です。
- 音声認識で選んだDeepgram / OpenAI / DeepLへタブ音声を送り、翻訳で選んだGemini / OpenAI / DeepL / DeepSeekへコメント・翻訳文・字幕原文を送ります。
- KeroTranslate独自の収集サーバー、解析SDK、翻訳履歴保存はありません。
- Deepgramには `mip_opt_out=true` を付けています。各Providerのデータ利用条件・無料枠・料金は契約によって異なります。
- 自動の有料Provider切替は行いません。停止前に送信済みの処理はProvider側で課金される場合があります。

## 開発

依存ライブラリのインストールやビルドは不要です。Node.js 22以降を推奨します。

```powershell
node --test tests/*.test.js
node tools/check.js
./tools/package.ps1
```

`package.ps1` はmanifestからBetaの表示番号を同期し、拡張ZIPを作成します。テスト用の疑似通信は `tests/` 内にあり、拡張には含まれません。

| 場所 | 内容 |
|---|---|
| `extension/` | Chromeへ読み込む拡張本体 |
| `tests/` | 状態管理、字幕、Provider、YouTube入力、権限境界のテスト |
| `tools/` | バージョン表示同期・構文検査・ZIP作成 |
| `artifacts/` | 拡張の配布用ZIP |
| [設計](docs/DESIGN.jp.md) | 設計判断とProvider比較の記録 |
| [受入確認](docs/ACCEPTANCE.jp.md) | 実機確認手順・残作業 |

英語をメインドキュメントとし、日本語版は `.jp.md` に移しました。旧バージョンの記録にあるDemoや操作案内より、このREADMEの導入手順を優先してください。**Test overlay** は音声・APIを使わない表示診断として残しています。

### 翻訳なしで文字起こしだけ表示する

設定画面の **Captions → Caption mode → Transcription only (no translation)** を選んで保存し、メインパネルで **Start captions** を押してください。音声認識のAPIキーだけで使えます。認識途中の原文も表示し、字幕の翻訳APIは呼びません。音声認識サービスの料金・制限は引き続き適用されます。コメントの翻訳・re-MTLを使う場合は翻訳APIキーが別途必要です。
